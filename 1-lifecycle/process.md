# Модель життєвого циклу й процес

> Автор: Юра Кампов, спеціальність F2 «Інженерія програмного забезпечення».

## Модель: інкрементна

| Фактор | У проєкті | Тягне до |
|---|---|---|
| Вимоги змінюються? | так: спершу лише операції, потім зʼявилось «зберігати дані користувачів», далі — історія операцій | інкрементів |
| Ціна помилки | помірна: гроші навчальні, але неправильна сума — головний дефект банку | тестів на кожен інкремент |
| Замовник доступний | викладач — на парах, не постійно | інкременти під контрольні точки, а не щоденні ітерації |
| Команда | 1 людина | мінімум процесу, максимум автоматичних перевірок |

**Інкременти:** v0.1.0 — програма в одному файлі (оригінал) → v0.2.0 — модулі, збереження, тести, CI → v0.3.0 — історія операцій і безпека PIN → v1.0.0 — реліз ([release-plan](../5-management/release-plan.md)).

Каскад не підходить: вимогу «зберігати дані» автор сформулював уже після першої робочої версії — у каскаді вона б зламала пізній етап.

## Процес

- **Kanban** на одну людину: «У черзі → В роботі → Готово», WIP = 1. Беклог — [backlog.md](backlog.md).
- **«Готово»** = код у `main`, CI зелений, документ оновлено, для виправлення є регресійний тест.
- **Перевірка:** самоперевірка PR за чек-листом ([git-workflow](../3-implementation/git-workflow.md)) + CI на Ubuntu й Windows.
- **Ризик процесу:** автор один — немає незалежного ревʼю (bus factor = 1, [risks](../5-management/risks.md), R-01).
