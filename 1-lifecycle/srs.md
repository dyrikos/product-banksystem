# Специфікація вимог (SRS)

> Автор: Юра Кампов, спеціальність F2 «Інженерія програмного забезпечення». Версія 0.2, 09.11.2026.

## 1. Призначення

BankSystem — навчальна консольна банківська система: зберігає рахунки клієнтів і виконує операції з ними. Не призначена для справжніх грошей.

## 2. Користувачі

Клієнт банку — входить у свій рахунок або відкриває новий. Адміністратор — збирає програму, стежить за сховищем; у навчальному проєкті це автор.

## 4. Нефункціональні вимоги (ISO/IEC 25010)

| ID | Характеристика | Вимога | Перевірка |
|---|---|---|---|
| NFR-1 | Функціональна коректність | Суми точні до цента: 0 похибок округлення в будь-якій послідовності операцій | TC-05, TC-14, TC-36 |
| NFR-2 | Надійність | Збій посеред збереження не псує попередні дані; пошкоджене сховище не перезаписується, показується рахунок або причина помилки | TC-26…TC-29, TC-40, TC-37 |
| NFR-3 | Стійкість до вводу | Будь-який ввід — літери, порожній рядок, закритий ввід (EOF) — не призводить до падіння чи зациклення; EOF завершує програму ≤ 1 с | TC-02, TC-04, TC-32 |
| NFR-4 | Безпека | PIN — рівно 4 цифри; ≤ 3 спроби входу; сховище не потрапляє в git | TC-08, TC-09, TC-35; `.gitignore` |
| NFR-5 | Зручність | Людина, що бачить проєкт уперше, за README входить у рахунок ≤ 5 хв | інтервʼю ([interviews](../0-product/interviews.md)), план |
| NFR-6 | Переносимість | Збирається без попереджень на Windows (MinGW, MSVC) і Linux (GCC) | CI: Ubuntu + Windows |
| NFR-7 | Супроводжуваність | Логіка (`bank`, `money`, `storage`) не використовує консоль і покрита ≥ 25 модульними тестами | ревʼю коду, `ctest` |
| NFR-8 | Ефективність | Будь-яка операція з 10 000 рахунків — ≤ 100 мс | замір, план (v0.3) |

## 6. Глосарій

| Термін | Значення |
|---|---|
| Рахунок | номер `UA…`, власник, PIN, баланс у центах |
| Сховище | база SQLite `data/accounts.db`, де рахунки живуть між запусками |
| Валюта | долар США; програма показує суми як `$5500.50` (CR-05) |
| Центи | ціле число, 1/100 долара; 5500.50 = 550050 |
