## 1. Вибір місця за ціною помилки

| Місце | Що станеться з користувачем | Коли помітять | Шляхів |
|---|---|---|---|
| **`parse_money` + арифметика** | на екрані одна сума, на рахунку інша; зняття «недостатньо коштів», хоча гроші є | **через тижні**: похибка накопичується тихо | 6: ціле, з копійками, 1 знак, порожньо, сміття, 3 знаки |
| **`load_accounts` / `save_accounts`** | втрата всіх рахунків | одразу, але вже пізно | 5: немає, порожнє, норм, пошкоджене, дубль |
| **`authenticate`** | хтось у чужому рахунку | можливо, ніколи | 3: збіг, не збіг, невідомий номер |

**Чим пізніше помітять, тим раніше тестуємо:** першими — гроші (тихий дефект), потім вхід, потім сховище.

## 2. Таблиці тест-кейсів

Стовпець «очікувано» заповнено **до** запуску. 🔴 — впало першим запуском.

### `money`

| № | Вхід | Клас / межа | Очікувано |
|---|---|---|---|
| 1 | `12`, `12.5` | типовий | `12.00`, `12.50` |
| 2 | `0.01` | межа: найменша сума | `0.01` |
| 3 | `abc`, порожньо | недійсний | відмова |
| 4 | `10.999` | межа: 3 знаки | відмова 🔴 |
| 5 | `100abc` | недійсний: сміття в кінці | відмова 🔴 |
| 6 | `0.10 + 0.20` | типовий для похибки `double` | рівно `0.30` 🔴 |

### `bank`

| № | Вхід | Клас / межа | Очікувано |
|---|---|---|---|
| 1 | правильні номер і PIN | типовий | вхід |
| 2 | PIN `0123`, ввести `123` | межа: провідний нуль | відмова 🔴 |
| 3 | PIN `1234`, ввести `1234x` | недійсний | відмова 🔴 |
| 4 | зняти рівно баланс / баланс + 0.01 | межі | `Ok`, 0.00 / `InsufficientFunds` |
| 5 | 0.30 − 0.10 − 0.20 | типовий з копійками | обидва `Ok` 🔴 |
| 6 | переказ собі / на невідомий рахунок | недійсні | `SameAccount` / `NotFound` |

### `storage`

| № | Вхід | Клас / межа | Очікувано |
|---|---|---|---|
| 1 | 2 рахунки з апострофом і PIN `0123` | типовий | однакові після збереження й читання 🔴 |
| 2 | сховища немає | межа: перший запуск | `nullopt` без помилки |
| 3 | 0 рахунків | межа | порожній список 🔴 |
| 4 | баланс `abc` у 3-му рядку | недійсний | помилка з «line 3» 🔴 |
| 5 | два рахунки з одним номером | повтор | помилка 🔴 |

Перевірка сусіда: у кожній таблиці ≥ 2 межових і ≥ 1 недійсний — так.

## 3. Червоне перед зеленим

Тест — три частини, одна причина падіння:

```cpp
TEST(withdraw_after_fractional_operations) {
    Bank b({make_account("Test", "UA1", "1111", "0.30")});   // дано
    Account* acc = b.find("UA1");
    CHECK(b.withdraw(*acc, m("0.10")) == Result::Ok);        // дія
    CHECK(b.withdraw(*acc, m("0.20")) == Result::Ok);        // перевірка
}
```

**Регресійні тести на код оригіналу.** Спершу код v0.1.0 перенесено в модулі **без зміни поведінки** (`double`, PIN `int`), потім написано тести з правильними очікуваннями:

```text
test_money.cpp:20: CHECK failed: !parse_money("10.999")
test_money.cpp:25: CHECK failed: !parse_money("100abc")
test_money.cpp:32: CHECK failed: sum == *parse_money("0.30")
2 passed, 3 failed
test_bank.cpp:37: CHECK failed: b.authenticate("UA0000000001", "123") == nullptr
test_bank.cpp:43: CHECK failed: b.authenticate("UA1223456789", "1234x") == nullptr
test_bank.cpp:81: CHECK failed: b.withdraw(*acc, m("0.20")) == Result::Ok
10 passed, 3 failed
```

Правки: копійки (`int64`), PIN-рядок, строгий розбір → **5 і 17 passed**.

**TDD для сховища.** `test_storage.cpp` написано до реалізації, проти заглушки → `1 passed, 6 failed`. Пройшов лише «сховища немає» — заглушка й так нічого не знаходить, тож цей тест нічого не доводить. Після реалізації — **7 passed**.

Тести на відкриття рахунку (TC-19…TC-22) написано **після** коду — їх не зараховую як «червоне перед зеленим».

## 4. Баг-репорт

Чужого модуля немає, тож дефект шукаю в **оригінальному** коді — так, як шукав би в коді сусіда: законним вводом, а не «рядок замість числа».

```text
Заголовок: При закритому вводі програма зациклюється (BUG-04)
Кроки:     printf 'UA1223456789\n1234\n2\n' | bank   — ввід закінчився, коли програма чекає суму
Очікувано: програма завершується
Фактично:  нескінченний цикл «Invalid input. Amount must be a positive number.» — 97 МБ виводу за 3 с
Оточення:  legacy/12main.cpp (v0.1.0), GCC 16.2, Windows 11
```

Усі 7 баг-репортів — [bug-reports.md](../4-quality/bug-reports.md).

## 5. Закриття дефекту: тест, потім правка

```bash
git switch -c fix/bug-04-eof
git add tests/ && git commit -m "test: закритий ввід не зациклює програму (BUG-04)"
git add src/main.cpp && git commit -m "fix: cli завершує роботу на кінці вводу (BUG-04)"
```

BUG-04 живе в діалозі `cli`, тому його регресійний тест — наскрізний сценарій TC-32: на v0.1.0 — зупинка таймаутом, на v0.2.0 — `Input closed. Goodbye!` і код 0.
