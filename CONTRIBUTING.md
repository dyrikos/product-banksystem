# Як ми працюємо

Домовленості проєкту BankSystem. Подробиці з прикладами — у [git-workflow.md](3-implementation/git-workflow.md).

## Гілки

- **Гілка на задачу**, від свіжого `main`: `feat/history`, `fix/bug-07-pin-lock`, `docs/srs`, `test/storage-edge-cases`.
- Гілка живе **не довше двох днів**. Не встигаєш — розбий задачу на менші.

## Коміти

Формат: `тип: що змінено` — зрозуміло без відкриття файлу.

| Тип | Коли |
|---|---|
| `feat:` | нова поведінка для користувача |
| `fix:` | виправлення дефекту (з номером: `fix: PIN порівнюється як рядок (BUG-02)`) |
| `test:` | тести без зміни поведінки |
| `docs:` | документи |
| `chore:` | збірка, налаштування |

## Злиття

- У `main` — через pull request за [шаблоном](.github/pull_request_template.md). Автор працює сам, тож ревʼю — самоперевірка за чек-листом у [git-workflow.md](3-implementation/git-workflow.md) і зелений CI; як зʼявиться друга людина — Approve дає вона.
- Перед злиттям локально: `cmake --build build && ctest --test-dir build --output-on-failure`.

## Код

- C++17, попередження компілятора — як помилки за змістом: збірка без жодного `warning`.
- Логіка — у `bank`, `money`, `storage` (без `std::cin`/`std::cout`); діалог — лише в `main.cpp`. Так логіку можна тестувати.
- Виправлення дефекту: **спершу тест, що відтворює його (червоний), потім правка** (зелений).

## Ніколи не потрапляє в git

`build/`, `data/` (там PIN клієнтів), `*.exe` — усе вже в `.gitignore`.
