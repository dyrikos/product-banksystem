# План підтримки

## Канал звернень

GitHub Issues за [шаблоном дефекту](../.github/ISSUE_TEMPLATE/bug_report.md). Відповідає автор — Юра Кампов.

## Види супроводу

| Вид | Що це | Приклад |
|---|---|---|
| Коригувальний | виправлення дефектів | BUG-01…BUG-07 |
| Адаптивний | зміни під нове середовище | нова версія компілятора, збірка на macOS |
| Удосконалювальний | нові функції | історія операцій (v0.3) |
| Превентивний | запобігання проблемам | хеш PIN, автоматичні наскрізні тести |

## Пріоритети звернень

| Пріоритет | Ознака | Приклад | Реакція |
|---|---|---|---|
| P1 — критичний | програма падає, зависає чи псує дані | сховище перезаписалось порожнім; зациклення | до наступної пари |
| P2 — високий | неправильна сума або вхід у чужий рахунок | баланс після переказу не той | ≤ 3 дні |
| P3 — середній | дефект з обхідним шляхом | кома в сумі не приймається | у наступній версії |
| P4 — низький | побажання | новий пункт меню | при плануванні |

## Як закривається звернення

Відтворити → регресійний тест (червоний) → правка (зелений) → рядок у [bug-reports](../4-quality/bug-reports.md) і [CHANGELOG](../CHANGELOG.md).
