# Тест-план

> Спрощений ISO/IEC/IEEE 29119-3. Версія 0.2, 09.11.2026. Автор і тестувальник — Юра Кампов, спеціальність F2 «Інженерія програмного забезпечення».

## 1. Обʼєкт і межі

**Тестуємо:** BankSystem v0.2.0 — модулі `money`, `bank`, `storage` і консольний діалог `cli`.

**Не тестуємо:** функції v0.3+ (історія, блокування, хеш PIN), роботу кількох копій програми одночасно, кирилицю в консолі Windows — див. [not-tested.md](not-tested.md).

**Вимоги-основа:** [srs.md](../1-lifecycle/srs.md); звʼязок — [traceability.md](../1-lifecycle/traceability.md).

## 2. Рівні

| Рівень | Що | Як | Коли |
|---|---|---|---|
| Модульний | `money`, `bank`, `storage` без консолі | автотести `ctest` (TC-01…TC-29, TC-38, TC-39), власний `check.h` | кожна збірка й кожен push (CI) |
| Інтеграційний | `storage` ↔ `bank` (round-trip рахунків), `cli` ↔ модулі | TC-23…TC-29 + наскрізні | кожен push / перед релізом |
| Системний | програма цілком: вхід, операції, перезапуск, EOF, пошкоджене сховище | наскрізні сценарії TC-30…TC-37: ввід подається в `bank` через `stdin` | перед кожним релізом |
| Приймальний | новачок за README входить у рахунок ≤ 5 хв (NFR-5) | інтервʼю з 5 одногрупниками ([plan](../0-product/interviews.md)) | перед v1.0.0 |
| Статичний | попередження компілятора | `-Wall -Wextra -Wpedantic` / `/W4` — збірка без жодного warning | кожна збірка |

## 3. Техніки

- **Класи еквівалентності й межові значення** для сум (0 / 0.01 / рівно баланс / баланс + 0.01; 2 і 3 знаки після коми), PIN (3 / 4 / 5 цифр, провідний нуль, сміття в кінці), імені (1 / 2 символи), сховища (немає / порожнє / пошкоджене / дубль).
- **Регресійні тести на дефекти оригіналу:** спершу тест, що падає на коді v0.1.0, потім правка ([test-report](test-report.md), розділ 2).
- **Наскрізні сценарії** через перенаправлення вводу: `printf '1\nUA1223456789\n1234\n5\n' | build/bank tmp.txt`.

## 4. Середовище

| | |
|---|---|
| Локально | Windows 11, GCC 16.2 (WinLibs MinGW-w64 UCRT), CMake 4.4 |
| CI | GitHub Actions: `ubuntu-latest` (GCC), `windows-latest` (MSVC) |
| Тестові дані | 3 демо-рахунки + рахунок із PIN `0123`; тимчасові сховища в теці збірки |

## 5. Критерії входу й виходу

- **Вхід:** проєкт збирається без попереджень.
- **Вихід (реліз):** усі автотести зелені на обох ОС у CI; усі наскрізні сценарії пройдено; немає відкритих дефектів «Критична» чи «Висока».

## 6. Ризики тестування

| Ризик | Реакція |
|---|---|
| Тестую власний код — «сліпа пляма» автора | регресійні тести на кожен знайдений дефект; інтервʼю з людьми, які не бачили код |
| MSVC поводиться інакше, ніж GCC | CI на `windows-latest` з MSVC |
| Наскрізні сценарії поки вручну | кандидат в автоматизацію: скрипт, що порівнює вивід із еталоном (v0.3) |
