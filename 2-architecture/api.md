# Контракт API компонента `bank`

> Автор: Юра Кампов, спеціальність F2 «Інженерія програмного забезпечення». **Версія контракту 1.0** (v0.2.0), 09.11.2026.

`bank` — бізнес-логіка: вхід, операції з грошима, відкриття рахунку. Програма консольна, тому API — це функції C++ (`src/bank.h`), а не HTTP. Компонент не читає консоль і не пише у файли: виклики детерміновані й тестуються без `cli` ([modules](modules.md)).

## Типи

| Тип | Опис |
|---|---|
| `Money` | `std::int64_t`, **копійки**: 5500.50 → `550050`. Межа балансу — `kMaxAmount` = 99 999 999 999 (999 999 999.99) ([ADR-0002](adr/0002-money-in-kopecks.md)) |
| `Account` | `owner` (2–50 символів), `number` (`UA` + цифри), `pin` (рядок рівно з 4 цифр), `balance` (`Money`) |
| `Result` | `Ok`, `InvalidAmount`, `InsufficientFunds`, `SameAccount`, `NotFound` |

## Операції

| # | Операція | Параметри | Успіх | Помилки |
|---|---|---|---|---|
| 1 | `authenticate(number, pin)` | номер рахунку, PIN рядком | `Account*` | `nullptr` — немає такого номера або PIN не збігся **точно** |
| 2 | `find(number)` | номер рахунку | `Account*` | `nullptr` — немає такого номера |
| 3 | `deposit(account, amount)` | рахунок, сума в копійках | `Ok` | `InvalidAmount` — сума ≤ 0 або баланс перевищить `kMaxAmount` |
| 4 | `withdraw(account, amount)` | рахунок, сума | `Ok` | `InvalidAmount` — сума ≤ 0; `InsufficientFunds` — сума > балансу |
| 5 | `transfer(from, to_number, amount)` | рахунок відправника, номер отримувача, сума | `Ok` | перевіряються **по черзі**: `SameAccount` → `NotFound` → `InvalidAmount` → `InsufficientFunds` |
| 6 | `open_account(owner, pin)` | імʼя, PIN | номер нового рахунку, баланс 0 | `nullopt` — імʼя або PIN некоректні |
| 7 | `parse_money(text)` (модуль `money`) | текст суми | `Money` | `nullopt` — не число, > 2 знаків після крапки, експонента, > 9 цифр цілої частини |

При будь-якій помилці стан рахунків **не змінюється**.

## Приклади запиту й відповіді

Стан перед кожним прикладом — демо-рахунки: `UA1223456789` (1234, 5500.50), `UA987654321` (5678, 1200.00).

| Операція | Запит | Відповідь | Тест-кейс |
|---|---|---|---|
| `authenticate` | `("UA1223456789", "1234")` | рахунок Yra Kampov | TC-06 |
| `authenticate` | `("UA1223456789", "1234x")` | `nullptr` | TC-09 |
| `deposit` | `(Polina, 10010)` — 100.10 | `Ok`, баланс `130010` | TC-10 |
| `deposit` | `(Yra, kMaxAmount)` | `InvalidAmount`, баланс `550050` | TC-39 |
| `withdraw` | `(Polina, 120001)` — 1200.01 | `InsufficientFunds`, баланс `120000` | TC-13 |
| `transfer` | `(Yra, "UA987654321", 50050)` | `Ok`, баланси `500000` / `170050` | TC-15 |
| `transfer` | `(Yra, "UA0000000099", 100)` | `NotFound`, баланси без змін | TC-17 |
| `open_account` | `("New Client", "0042")` | `"UA0000000004"` | TC-19 |
| `open_account` | `("Client", "12a4")` | `nullopt` | TC-21 |
| `parse_money` | `"12.5"` / `"10.999"` / `"1e3"` | `1250` / `nullopt` / `nullopt` | TC-01, TC-03, TC-38 |

## Правила контракту

- **Вказівники `Account*`** дійсні лише до наступного `open_account`: новий рахунок може перемістити вектор у памʼяті. `cli` тримає номер рахунку, а не вказівник.
- **Збереження — не справа `bank`.** Після `Ok` викликач сам зберігає рахунки через `storage`.
- **Версіонування.** Нова операція — мінорна версія (1.1). Зміна типу чи значення `Result` — мажорна (2.0) з записом у [changes](../1-lifecycle/changes.md). Наприклад, хеш PIN у v0.3 змінить `Account::pin`, тому це буде контракт 2.0.
