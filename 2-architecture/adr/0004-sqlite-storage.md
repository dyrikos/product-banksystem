# ADR-0004. Сховище — база SQLite

- **Статус:** прийнято, 09.11.2026. Замінює [ADR-0003](0003-text-file-storage.md).
- **Автор:** Юра Кампов
- **Повʼязано:** FR-06, NFR-2, R-04, R-06

## Контекст

Текстовий файл (ADR-0003) працював, але мав три слабкі місця:

- атомарність трималась на власному коді (тимчасовий файл і заміна);
- дві копії програми одночасно могли зіпсувати одна одній запис;
- історія операцій (FR-09) і блокування входу (FR-10) у v0.3 потребують ще таблиць — у текстовому форматі це довелося б вигадувати самим.

## Варіанти

| Варіант | Плюси | Мінуси | Рішення |
|---|---|---|---|
| 1. Лишити текстовий файл | нуль залежностей, читається в блокноті | без транзакцій і блокувань; нові таблиці — власний формат | ❌ |
| 2. **SQLite, вихідний код у репозиторії** (`third_party/sqlite`, 3.50.4) | транзакції, блокування файлу, обмеження в схемі, SQL для історії; нічого не треба встановлювати | +9 МБ коду в репозиторії; перша збірка довша | ✅ |
| 3. SQLite з системи (`find_package`) | репозиторій менший | на Windows бібліотеки зазвичай немає — збірка «з нуля за хвилину» ламається | ❌ |
| 4. Сервер БД (PostgreSQL) | багато клієнтів через мережу | окремий сервер для консольної програми з одним користувачем — надмірно | ❌ |

## Рішення

Файл `data/accounts.db`, таблиця `accounts`:

```sql
CREATE TABLE accounts (
  number  TEXT PRIMARY KEY,
  pin     TEXT NOT NULL CHECK (length(pin) = 4 AND pin NOT GLOB '*[^0-9]*'),
  balance INTEGER NOT NULL CHECK (balance BETWEEN 0 AND 99999999999),
  owner   TEXT NOT NULL
);
```

- Версія схеми — `PRAGMA user_version = 1`. Новіша версія, ніж знає програма, — помилка, а не мовчазне читання.
- Збереження — одна транзакція (`BEGIN IMMEDIATE … COMMIT`); при будь-якій помилці `ROLLBACK`, старі дані лишаються (TC-29).
- Читання відкриває базу **лише для читання** і перевіряє кожен рядок, бо базу могли змінити стороннім інструментом (TC-27, TC-28). Пошкоджена база не перезаписується (TC-37).
- Модуль `storage` зберіг той самий контракт (`load_accounts` / `save_accounts`): зміна не зачепила `bank`, `money` і тести інших модулів.

## Наслідки

- ➕ Надійність запису дає SQLite, а не наш код; дві копії програми не зіпсують файл (блокування + `busy_timeout` 2 с).
- ➕ Схема сама відкидає PIN не з 4 цифр, відʼємний баланс і дублікат номера.
- ➕ Історія операцій у v0.3 — ще одна таблиця й `INSERT`, без нового формату.
- ➖ Файл не відкрити в блокноті — потрібен DB Browser for SQLite або `sqlite3` ([runbook](../../5-management/runbook.md)).
- ➖ Дві копії програми досі можуть перезаписати **зміни** одна одної: кожна зберігає весь список рахунків. Файл цілий, але виграє останній запис ([R-06](../../5-management/risks.md)). Розвʼязок — зберігати лише змінені рахунки (v0.3).
- ➖ PIN досі відкритим текстом — хеш у v0.3 (R-03).
