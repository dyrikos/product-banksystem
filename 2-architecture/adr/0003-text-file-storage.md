# ADR-0003. Сховище — текстовий файл з атомарним записом

- **Статус:** замінено [ADR-0004](0004-sqlite-storage.md) (SQLite), 09.11.2026
- **Автор:** Юра Кампов
- **Повʼязано:** FR-06, BUG-05, NFR-2

## Контекст

Задум автора — «записувати дані користувачів», але у v0.1.0 рахунки жили лише в памʼяті й зникали після виходу. Потрібно зберігати рахунки між запусками без сторонніх бібліотек ([ADR-0001](0001-cpp-console.md)).

## Варіанти

| Варіант | Плюси | Мінуси | Рішення |
|---|---|---|---|
| 1. Двійковий файл (`write` структур) | швидко | не прочитати очима; залежить від компілятора й платформи | ❌ |
| 2. SQLite | транзакції, запити | стороння бібліотека; надмірно для десятків рахунків | ❌ поки що |
| 3. JSON | поширений формат | потрібна бібліотека (nlohmann/json) або власний парсер | ❌ |
| 4. **Текстовий файл `номер;pin;копійки;імʼя` + запис через тимчасовий файл** | читається очима, правиться в блокноті, нуль залежностей | без транзакцій; один процес за раз | ✅ |

## Рішення

`data/accounts.txt`: перший рядок `# BankSystem accounts v1`, далі рядок на рахунок. Імʼя — останнє поле, бо може містити пробіли; `;` в імені заборонено (`valid_owner`). Збереження: пишемо `accounts.txt.tmp`, потім замінюємо ним основний — збій посеред запису лишає старий файл цілим. Під час читання кожен рядок перевіряється (номер, PIN, сума, імʼя, дублікати); помилка — з номером рядка, і програма **не** перезаписує пошкоджене сховище.

## Наслідки

- ➕ Баланс переживає перезапуск (TC-31), пошкодження помітне (TC-37).
- ➖ PIN лежать відкритим текстом — сховище в `.gitignore`, хеш PIN — у v0.3 ([risks](../../5-management/risks.md), R-03).
- ➖ Дві копії програми одночасно перезапишуть зміни одна одної. Для навчальної моделі прийнятно; для кількох користувачів — SQLite (варіант 2).
